# SI사업2팀 주간업무 보고

주간보고 작성, 제출 현황, 본사·프로젝트 인력 관리, 상사 보고용 엑셀 취합을 위한 반응형 웹앱/PWA 미리보기입니다.

## 실행

정적 파일을 제공하는 로컬 HTTP 서버에서 실행합니다. PWA 서비스 워커는 `file://` 대신 `localhost` 또는 HTTPS에서 동작합니다.

```powershell
cd D:\weekly-web-app
py -m http.server 4173
```

브라우저에서 `http://localhost:4173`을 엽니다. 설치 가능한 브라우저에서는 메뉴에서 앱 설치 또는 홈 화면에 추가를 선택할 수 있습니다.

## 현재 제공 기능

- 주간 대시보드와 본사 근무자 제출 현황
- 지난주 보고를 불러와 수정한 뒤 제출하는 입력 화면
- 본사/프로젝트 인력 구분, 추가, 근무 상태 변경, 비활성 처리
- 취합 화면에서 주간보고 시트와 인력 현황 시트가 있는 `.xlsx` 파일 다운로드
- 브라우저 로컬 저장, 서비스 워커 캐시 및 브라우저 알림 설정

팀원 직급·직무·직책은 `팀원명단.xlsx`를 반영합니다. 근무 구분과 프로젝트 내용은 2026년 10월 5일 주간 보고서를 기준으로 하며, 해당 문서에 10월 7일 프로젝트 철수로 기재된 김이슬님은 본사 근무로 분류했습니다. 업무 상세와 제출 시각은 화면 흐름을 보여주기 위한 예시입니다.

## 운영 적용에 필요한 연결

현재 화면은 아직 `localStorage` 미리보기이며 Supabase와 연결되어 있지 않습니다. 지정된 Supabase 프로젝트에는 `members`와 `weekly_reports` 테이블이 이미 있지만 RLS가 비활성화되고 정책도 없는 상태로 확인했습니다. 브라우저에서 데이터를 열기 전에 로그인 사용자와 팀원 연결, 팀원/팀장 쓰기 권한 정책을 적용해야 합니다. 보고 내용은 로그인한 팀원 모두가 볼 수 있도록 한다는 선택은 반영하되, 이 설정 전에는 원격 DB에 읽기/쓰기를 하지 않습니다.

최신 팀원 명단에는 이메일 주소가 없습니다. Supabase Auth 계정과 팀원 레코드를 연결하려면 회사 이메일 주소가 필요합니다. 팀 전체 운영에는 사용자 로그인, 공유 데이터베이스/API, 서버에서 실행되는 목요일 예약 작업, 이메일 또는 푸시 발송 서비스, HTTPS 배포가 필요합니다. 실제 메일 발송과 배포에는 회사에서 사용할 계정/서비스와 발송 권한이 준비되어야 합니다.
